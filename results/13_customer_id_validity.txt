# Do Customer IDs behave like real, consistent customers?

Statistics inside the shuffled 95% range (no tolerance added): 6 of 6. The six statistics are related, so this is one consistent pattern, not six independent confirmations.
Power check: if just 10% of visits repeated the previous branch (a weak habit), 'same branch' would be 0.433 vs the shuffled range 0.369-0.383. Illustrative sensitivity check only (one injected pattern, one feature) - not a power estimate.

Conclusion: real customers usually have habits - a usual branch, order type, time and products. Visits sharing a Customer ID show no detectable persistence beyond randomly shuffled labels on any tested feature (an illustrative check suggests a modest branch habit would have shown). That does not prove the IDs are meaningless (prepared or anonymised data can behave like this), but it means they cannot be trusted for longitudinal analysis until ID assignment is validated. Consequences: (1) anything built on following an ID over time - branch switching, return visits, 'the same regulars', customer concentration - describes the labels, not behaviour, and is withdrawn or downgraded in the README; (2) aggregate findings (traffic, margins, costs, prices, timing) do not use IDs and are unaffected; (3) business value: Stories should NOT invest in CRM/loyalty analytics or ID-based targeting on this data until ID capture is fixed - test: check how IDs are assigned at the till for one week at one branch.
